# Contributing

1. Start from an approved product work package with explicit acceptance criteria.
2. Keep products isolated; never hard-code credentials or signing keys.
3. Pin toolchain and dependency versions.
4. Test user-visible behavior, not merely process startup or compilation.
5. Never claim completion from a successful compile alone.
6. Record known limitations and exact verification commands.

Pull requests must state the user problem, behavior delivered, tests and results, permission/privacy/security impact, and artifact or CI evidence.

Definition of done: acceptance criteria pass, tests are reproducible, no secrets are committed, and release notes accurately describe limitations.
